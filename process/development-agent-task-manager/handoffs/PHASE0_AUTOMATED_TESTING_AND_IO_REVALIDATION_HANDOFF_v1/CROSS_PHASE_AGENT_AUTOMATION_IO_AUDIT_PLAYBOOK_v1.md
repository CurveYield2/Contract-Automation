# Cross-Phase Agent vs Automation I/O Audit Playbook v1

## Goal

After any substantial workflow/authority change, verify that every agent action and every automated action agree on:

- who owns each datum;
- where it is written;
- what schema validates it;
- what automation reads it;
- what downstream phase receives it;
- what is canonical versus derived;
- what is read-only;
- what is controller-generated;
- what is bookkeeping versus semantic work.

This is the methodology that found the v10.3 interface defects.

## The 12-layer interface trace

For every phase/action, trace the datum through all applicable layers:

1. **Agent instruction**
   - exact action title;
   - exact Step X section name;
   - semantic responsibility;
   - explicit controller-owned/read-only exclusions.

2. **Phase contract**
   - step action;
   - required inputs;
   - output destination;
   - requiredFields;
   - post-validation automation.

3. **Phase schema**
   - action title;
   - section;
   - field names/types;
   - required record fields;
   - allowed enums;
   - consumers;
   - controller prefill/collected/generated metadata.

4. **Work-form template**
   - exact action/section;
   - exact output keys;
   - complete item keys;
   - placeholders match ownership.

5. **Prefill automation**
   - source artifact;
   - path;
   - exact generated record shape;
   - read-only fields;
   - integrity digest coverage.

6. **Validator**
   - completeness;
   - enums;
   - controller ownership/tamper detection;
   - row coverage;
   - source/build identity;
   - cross-field rules.

7. **Canonicalization**
   - accepted reviewer fields;
   - controller-generated outputs;
   - canonical IDs;
   - no hidden undeclared fields.

8. **Bookkeeping**
   - traceability graph;
   - obligation ledger;
   - invalidation matrix;
   - no non-obligation data sent to obligation mapping;
   - no later phase re-bookkeeping.

9. **Derived outputs**
   - selectors reference declared action/controller outputs;
   - correct source phase;
   - complete enough for consumer;
   - no redundant metadata copies.

10. **Next-phase assignment**
    - exact derived paths;
    - prefills exist before reviewer wake;
    - controller report path may be absent until end-of-phase;
    - no incoming active receipt assumption;
    - wake wording matches ownership.

11. **Boundary machine execution**
    - input schema matches runner;
    - exact request/source/candidate identity binding;
    - result renderer matches next form;
    - machine facts and semantic interpretation are separated.

12. **Final evidence**
    - findings;
    - candidate dispositions;
    - obligations;
    - limitations;
    - remediation state;
    - Full-only omissions;
    - decisive evidence;
    - no earlier limitation disappears.

## Required exact comparisons

For phases 1–6 and 8–10:

- \`PHASE_CONTRACT.steps[N].action == PHASE_SCHEMA.actions.step-N.title\`
- contract output section == schema section == form section == START_HERE referenced section
- contract requiredFields == schema field names
- form output keys == schema field names
- record template includes every itemRequiredField
- controller-prefilled/collected keys exist in schema/template
- schema derived outputs == contract derivedOutputPolicy outputs
- bookkeeping paths refer only to declared agent outputs or declared controller-generated outputs
- final-report template has every schema required section

For automation-only phases 0 and 7:

- declared outputs == automation-produced/finalizer-required outputs
- hard-coded marker record shape == schema/template
- no substantive reviewer obligation targets Phase 7

## Ownership tests

Every field belongs to exactly one primary owner class:

- REVIEWER_SEMANTIC
- CONTROLLER_PREFILL_READ_ONLY
- CONTROLLER_COLLECTED
- CONTROLLER_GENERATED
- MACHINE_EXECUTION
- CANONICAL_BOOKKEEPING

Red flag: the same fact is manually entered by an agent and regenerated by automation.

Red flag: an automation-only datum is mutable without controller-backed integrity protection.

Red flag: code materializes a field that the schema does not declare.

## Known defect classes to actively search for

The v10.3 pass found examples of each:

- action title drift;
- form field missing from template;
- controller output used by selector but undeclared in schema;
- finalizer-required output absent from Phase-0 contract;
- stale “submit Phase Work Packet” wake language;
- incoming final report required before reviewer work;
- automation-only Phase 7 receiving substantive obligations;
- non-obligation records mapped into obligation ledger;
- due obligation rows not actually prefilled;
- final evidence index dropping earlier limitations;
- local prefill digest stored only in reviewer-editable form;
- campaign-relative vs repo-relative execution request paths;
- test target semantics not bound to exact request/harness;
- controller-collected fields added after validation without re-binding ownership.

Search deliberately for these patterns after every future refactor.

## Cross-repo workflow

1. Read current live authority first.
2. Create paired branches.
3. Patch authority and automation together.
4. Add validator rules that make the repaired invariant permanent.
5. Add unit/integration tests for the exact defect.
6. Open paired PRs.
7. Run full Contract-Automation qualification against matching Audit-Controller branch.
8. Diagnose every failure.
9. Repair implementation or stale tests; do not weaken valid invariants.
10. Merge only after paired validation is green.
11. Verify main-branch qualification.
12. Verify authority ZIP sync.
13. Repeat this playbook on the merged state.

## Evidence standard for “clean”

A clean result means:

- no unexplained static mismatch;
- no hidden controller field;
- no dead agent field;
- no missing required machine artifact;
- no consumer without producer;
- no producer without declared consumer/purpose;
- no read-only field outside assignment-backed integrity;
- no stale handoff/wake ownership language;
- all CI/qualification checks green.

Do not equate “tests passed” with “interfaces verified” unless this trace was also completed.
